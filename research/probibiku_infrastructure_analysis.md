# АвтоЛог — Анализ инфраструктуры
*Оценка предложенного стека на Yandex Cloud*

---

## Общая оценка

Предложенное решение хорошо адаптировано под российский рынок. Yandex Cloud как единая экосистема — правильный выбор. Yandex Object Storage полностью совместим с S3 API, поэтому код остаётся переносимым. Бюджет 1200–2000 руб./мес. является конкурентным для данного класса продуктов.

---

## Сильные стороны

- **Yandex Vision OCR** — лучшее качество распознавания кириллицы на мятых чеках, лучше Google Vision.
- **Единая экосистема** — Object Storage, Compute Cloud и Managed PostgreSQL в одном биллинге и дашборде.
- **S3-совместимость** — код для работы с хранилищем переносим без изменений.
- **Низкая стоимость** — ~1200–2000 руб./мес. покрывает полноценный MVP.

## Нюансы и рекомендации

### ВМ вместо serverless-хостинга

Это принципиальный выбор. Для соло-разработчика означает самостоятельное управление сервером: настройка reverse proxy, SSL-сертификаты, обновления ОС, мониторинг. Не критично, но закладывайте +2–3 часа на первоначальную настройку.

**Рекомендация:** использовать Caddy вместо Nginx — автоматически получает и обновляет SSL от Let's Encrypt без дополнительной конфигурации.

### 20% гарантированная доля vCPU

Правильный выбор для старта по стоимости. При нескольких одновременных OCR-запросах (загрузка фото → API → ожидание ответа) возможно проседание. На раннем MVP не критично.

**Рекомендация:** поднять до 50–100% при достижении 500+ активных пользователей.

### PostgreSQL на Docker (MVP-этап)

Разумное решение, позволяющее сэкономить на управляемой БД. Главный риск — отсутствие автоматических бэкапов из коробки.

**Рекомендация:** в первый же день настроить `pg_dump` по крону с выгрузкой в Object Storage. Потеря данных пользователей при инциденте с диском недопустима на любом этапе.

### Выбор ORM

Из двух предложенных вариантов (Prisma / Drizzle) рекомендуется **Drizzle ORM**. Prisma генерирует тяжёлый бандл и медленнее стартует. Drizzle описывает схему как чистый TypeScript, что значительно лучше поддерживается AI-ассистентами.

### Выбор Auth-провайдера

Из двух вариантов (NextAuth.js / Clerk) рекомендуется **NextAuth.js**. Clerk удобнее в настройке, но добавляет зависимость от внешнего сервиса. NextAuth.js полностью self-hosted, что логично в контексте всей остальной инфраструктуры на Yandex Cloud.

## Чеклист запуска

- [ ] Поднять ВМ на Ubuntu 22.04/24.04, настроить Caddy + автоматический SSL
- [ ] Запустить PostgreSQL в Docker, настроить `pg_dump` → Object Storage (крон)
- [ ] Создать бакет в Yandex Object Storage, выдать сервисный аккаунт с нужными правами
- [ ] Настроить NextAuth.js с Яндекс OAuth и Email OTP (Nodemailer)
- [ ] Подключить Yandex Vision OCR API, проверить качество на тестовых чеках
- [ ] Интегрировать YandexGPT для структурирования данных, настроить системный промпт
- [ ] Настроить CI/CD (GitHub Actions → SSH deploy на ВМ)

## Добавление LLM-слоя (YandexGPT)

Включение нейросети для парсинга данных меняет архитектуру с "простого хранилища" на "интеллектуального ассистента".

### Преимущества:
- **Zero Data Entry:** Пользователь вообще не вводит данные руками.
- **Гибкость:** Нейросеть понимает документы разных дилеров (Genser, Рольф, локальные СТО).

### Риски и решения:
- **Задержка (Latency):** Ответ от LLM может занимать 3-7 секунд. 
    - *Решение:* UI должен быть оптимистичным — показывать анимацию "Разбираю почерк механика..." и выполнять обработку в фоновом режиме через асинхронную очередь.
- **Стоимость:** Каждый запрос стоит денег.
    - *Решение:* Кэшировать результаты и ограничивать количество бесплатных распознаваний для защиты от злоупотреблений.
- **Галлюцинации:** Нейросеть может ошибиться в цифре артикула.
    - *Решение:* Обязательный экран подтверждения (Review Step), где найденные данные подсвечиваются поверх оригинального фото.
